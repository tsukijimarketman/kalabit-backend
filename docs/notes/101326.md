
# What I Learned Today

Today, I learned several important concepts related to **C#, Entity Framework Core, entity relationships, and unit testing**. These concepts helped me understand how to manage data, configure entity properties, write cleaner code, and verify application behavior through automated tests.

## 1\. Enums and String Conversion in Entity Framework Core

I learned about **enums in C#** and how they are represented when stored in a database. Enum members have underlying numeric values by default.

For example:

```
public enum AnimalType
{
    Cats,
    Dogs,
    Mouse
}
```

By default, the values are:

- `Cats` = `0`
- `Dogs` = `1`
- `Mouse` = `2`

Entity Framework Core allows us to store enum member names as strings instead of their numeric values by using `.HasConversion<string>()`.

```
builder.Property(entity => entity.AnimalType)
    .HasConversion<string>();
```

With this configuration, the database stores values such as `Cats`, `Dogs`, and `Mouse` instead of `0`, `1`, and `2`. This makes database records easier to read and understand.

However, renaming enum members may require updating existing database values.

## 2\. ValueGeneratedNever() and GUID Version 7

Another important lesson I learned is the purpose of **`.ValueGeneratedNever()`** in Entity Framework Core.

This configuration tells EF Core that a property should not be treated as a database-generated value. It is useful when the application generates its own primary key instead of relying on the database.

```
builder.Property(entity => entity.Id)
    .ValueGeneratedNever();
```

In my case, I am using `Guid.CreateVersion7()` to generate GUIDs as primary keys.

```
public Guid Id { get; init; } = Guid.CreateVersion7();
```

Version 7 GUIDs incorporate a timestamp and have a time-ordered structure, which can help improve database index locality compared with randomly ordered GUIDs.

### get; set; vs. get; init;

I also learned the difference between `{ get; set; }` and `{ get; init; }` in C#.

- **`{ get; set; }`** allows a property to be reassigned after an object is created.
- **`{ get; init; }`** generally restricts assignment to object initialization.

Using `{ get; init; }` for an identifier communicates that the ID should be established when the object is created and should not be freely modified afterward.

## 3\. ICollection\<T\> and Entity Relationships

I learned about **`ICollection<T>`** and how it represents relationships between entities in Entity Framework Core.

A collection navigation property allows an entity to reference multiple related entities. For example, a client may have multiple orders.

```
public class Client
{
    public Guid Id { get; init; } = Guid.CreateVersion7();

    public ICollection<Order> Orders { get; set; }
        = new List<Order>();
}
```

Entity Framework Core can use the `Orders` navigation property to represent the relationship between clients and orders. These relationships can also be used in LINQ queries to retrieve related data.

For example:

```
var clients = await context.Clients
    .Include(client => client.Orders)
    .ToListAsync();
```

The `.Include()` method requests **eager loading** of related orders alongside the clients.

However, declaring an `ICollection<T>` property alone does not automatically load related data. The relationship must be recognized or configured in the EF Core model, and related data must be loaded through an appropriate mechanism.

## 4\. Switch Expressions in C#

I learned about **switch expressions**, which provide a concise alternative to traditional switch statements when we want to produce a value.

### Traditional switch statement

```
switch (animalType)
{
    case 1:
        return "Cats";

    case 2:
        return "Dogs";

    default:
        return "Unknown";
}
```

### Switch expression

```
var animal = animalType switch
{
    1 => "Cats",
    2 => "Dogs",
    _ => "Unknown"
};
```

In a switch expression, `=>` separates each pattern from the value it produces, while `_` matches any value not handled by the preceding arms.

This approach reduces boilerplate and makes code easier to read when mapping inputs to results.

The key difference is that a traditional switch statement executes statements, while a switch expression evaluates to a value.

## 5\. Unit Testing with xUnit

Finally, I learned about **xUnit**, a unit testing framework for .NET that is conceptually similar to Jest in JavaScript.

It allows developers to write automated tests to verify whether a piece of code behaves as expected.

One of the fundamental concepts in unit testing is comparing the **expected result with the actual result**.

- **Expected result:** The value we want the code to produce.
- **Actual result:** The value the code produces when executed.

For example, consider a method that adds two numbers:

```
public int Add(int a, int b)
{
    return a + b;
}
```

We can test this method using xUnit:

```
using Xunit;

public class CalculatorTests
{
    [Fact]
    public void Add_TwoNumbers_ReturnsTheirSum()
    {
        // Arrange
        var calculator = new Calculator();

        // Act
        var actual = calculator.Add(2, 3);

        // Assert
        Assert.Equal(5, actual);
    }
}
```

The `[Fact]` attribute identifies a test method, while `Assert.Equal(5, actual)` compares the expected value, `5`, with the actual result.

If the values match, the assertion passes. Otherwise, the test fails.

### Arrange, Act, Assert (AAA)

I also learned about the **Arrange, Act, Assert (AAA) pattern**, which provides a consistent structure for writing tests.

- **Arrange:** Prepare the objects, inputs, and dependencies needed for the test.
- **Act:** Execute the method or behavior being tested.
- **Assert:** Verify that the actual result matches the expected result.

Unit testing helps identify bugs early and detect regressions when existing code changes. Instead of manually checking behavior every time, we can rerun automated tests to verify that the code continues to work as expected.

## Technical Takeaways

- **Enums in C#:** Enum members have underlying numeric values by default, starting at `0` unless explicitly assigned otherwise.
- **Enum string conversion:** `.HasConversion<string>()` configures EF Core to store enum member names instead of their numeric values.
- **`.ValueGeneratedNever()`****:** Configures EF Core not to treat a property as database-generated.
- **`Guid.CreateVersion7()`****:** Generates a time-ordered GUID that can help with database index locality.
- **`{ get; set; }`****vs.****`{ get; init; }`****:** `set` allows reassignment after initialization, while `init` generally restricts assignment to object initialization.
- **`ICollection<T>`****:** Represents a collection of related entities through a navigation property.
- **`.Include()`****:** Requests eager loading of related entities in an EF Core query.
- **Switch expressions:** Use `=>` to map patterns to result values and `_` as a catch-all pattern.
- **xUnit:** A .NET testing framework used to write and execute automated tests.
- **Expected vs. actual:** `Assert.Equal(expected, actual)` verifies that the actual result matches the expected value.
- **Arrange, Act, Assert:** A common pattern for organizing tests into preparation, execution, and verification.
- **Regression testing:** Rerunning automated tests helps identify whether code changes have broken existing functionality.

## Key Takeaway

Good software development involves understanding how language features, ORM configurations, and testing tools work together. By choosing appropriate enum conversions, controlling identifier generation, modeling entity relationships correctly, writing concise switch expressions, and testing expected behavior with xUnit, we can build applications that are easier to understand, maintain, and extend with confidence.
